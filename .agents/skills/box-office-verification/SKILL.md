# 박스오피스 데이터 검증

변경이 영향을 주는 데이터 경로를 골라 기대값과 실제 결과를 비교한다. 검증 범위는 해당 변경과 관련 회귀 위험으로 한정한다. 단순 표시 변경이라도 단위·반올림·날짜 범위·필터·차트 숫자 변환을 바꾸면 이 Skill을 적용한다.

## ① 입력과 기준 찾기

1. 프로젝트 루트의 [AGENTS.md](../../../AGENTS.md)를 읽고 변경 요청과 diff에서 영향을 받는 입력·함수·테이블·출력을 찾는다. 이 Skill 자체의 작성이나 문서 검토를 애플리케이션 검증 실행으로 간주하지 않는다.
2. 필요한 기준만 읽는다.
   - 기대 동작·AC·집계 규칙: [PRD.md](../../../PRD.md)
   - 외부 연동·응답 상태·캐시·실패 정책: [ARCHITECTURE.md](../../../ARCHITECTURE.md)
   - PK/FK·세 테이블 저장·원자적 교체: [ERD.md](../../../ERD.md). JSONB 캐시보다 후속 정규화 설계를 적용한다.
3. 각 검사에 입력, 기대 결과, 근거 문서/AC를 먼저 정한다. 구현에서 나온 값을 그대로 기대값으로 복사하지 말고 작은 고정 fixture와 독립적인 수기 계산 또는 SQL로 비교한다.
4. 실제 `package.json`, 기존 테스트·fixture·마이그레이션·사용 가능한 로컬 DB를 확인한다. `test`, `typecheck`, `lint`, `build`는 정의되어 있을 때만 사용한다. AGENTS.md의 ‘미정’을 실행 가능하다고 추정하지 않는다.
5. 기본 입력은 비밀값 없는 가상 fixture다. `KOBIS_API_KEY`, `SUPABASE_SECRET_KEY`는 이름만 언급하고 실제 값과 `.env.local` 내용을 출력하지 않는다. 실제 KOBIS 호출이나 공유·운영 DB 변경 권한을 이 Skill 호출만으로 추정하지 않는다. DB 쓰기는 격리된 로컬/테스트 DB와 폐기 가능한 데이터로 수행한다.

## ② 변경에 맞춘 검사 선택

아래에서 변경에 해당하는 행을 선택한다. 여러 경로가 바뀌면 관련 검사를 조합하고, 필요하면 파싱 → 저장 → 재조회 → 집계까지 한 번의 통합 경로를 확인한다.

| 변경 영역 | 선택할 검사 | 기대 결과 |
| --- | --- | --- |
| 응답 파싱·정규화 | 유효한 일간/주간·주말 fixture, 정상 빈 배열, 목록 필드 누락, 외부 오류 객체, 필수 숫자의 빈 문자열·비숫자·소수·누락 | 유효한 응답만 수용. 빈 배열은 정상 `empty`, 구조·값 오류는 `error`. 잘못된 값을 0으로 대체하지 않음 |
| 숫자 정밀도·직렬화 | `"900"`과 `"1000"` 합산·비교, 안전 정수 범위를 넘는 정수, DB 범위 초과, JSON 왕복·차트 변환 | 합계 1,900, 숫자 기준 비교. 큰 정수는 서버 `bigint`와 십진 문자열 경계를 지나도 보존. 범위 초과를 감지하고 조용히 반올림하지 않음 |
| DB 저장·갱신 | 영화 2개×날짜 3일 저장 후 JOIN, 동일 기간·영화 재저장, 없는 부모 FK, 같은 날짜의 다른 기간 유형, 기존 목록에서 영화가 빠진 갱신 | PK 중복 없이 멱등 저장, 잘못된 FK 차단, 일간/주간/주말 분리, 제거된 영화의 이전 실적도 삭제 |
| 원자성·빈 결과 저장 | 중간 저장 실패 주입, `data`→`empty` 갱신, 외부 실패 후 재조회 | 실패 시 전체 롤백·이전 정상 데이터와 TTL 보존. 정상 빈 결과는 기간 행 유지·실적 0행. 오류를 `empty`로 저장하지 않음 |
| 캐시·동시 갱신 | 유효 캐시, 없음/만료, 만료 경계의 고정 시각, 외부 실패, 같은 키 동시 요청 | 유효 캐시에서 외부 호출 생략, 만료 시 갱신, 읽기만으로 TTL 연장 금지. 실패 시 만료값을 최신으로 제공하지 않음. 중복 갱신과 늦은 소유자의 쓰기 차단 |
| 기간·추이·Top | 종료일 포함 7/14/30일, 날짜 순서, `movieCd`별 합산, 같은 제목의 다른 코드, 동률·N개 미만, 누적 수치가 기간 합계와 다른 fixture | 일간 `salesAmt`·`audiCnt`만 합산. 누적값 합산 금지. 매출 내림차순→관객수 내림차순→코드 오름차순. F1 필터가 F2에 영향 없음 |
| 보조 지표·표시 | 총매출·총관객수 수기 대조, 1위 매출 점유율, 반올림 경계, 분모 0, 단위·포맷 | PRD 산식과 소수점 한 자리 반올림 일치. 분모 0은 ‘—’. 원/명 단위와 정확한 정수 표시 |
| 결측·오류·검색 상태 | 전체 빈 기간, 일부 정상 빈 날짜, 하루 API 실패, 원본은 있지만 검색 결과 없음·검색 초기화 | 정상 빈 날짜는 차트 공백과 유효 날짜 수 표시. 하루라도 오류면 확정 Top·총합 중단. 검색 결과 없음은 전용 안내·초기화, 원본 빈 목록은 정상 빈 안내 우선 |

- 부호 허용 등 외부 계약이 미정인 값은 임의로 유효/무효를 확정하지 않는다. 근거를 확인할 수 없으면 해당 계약 검사를 미실행으로 남긴다.
- fixture 기반 단위 검사로 확인할 수 있는 내용과 실제 DB 제약·트랜잭션 검사를 구분한다. 모의 DB 통과만으로 실제 FK·롤백을 검증했다고 쓰지 않는다.
- 관련 스크립트를 실행하고 종료 코드뿐 아니라 기대값과 관찰 결과를 확인한다. 타입 검사·빌드 통과만으로 계산 정확성을 판정하지 않는다.
- 테스트 도구가 없으면 독립적인 작은 검증 코드나 수동 대조를 사용할 수 있다. 사용 방식과 한계를 남기고, 도구 설치나 테스트 체계 전체 구축으로 범위를 자동 확대하지 않는다.

## ③ 결과와 중단 기준

각 검사 결과는 다음 세 상태 중 하나로 보고한다.

| 상태 | 판정 기준 | 보고할 근거 |
| --- | --- | --- |
| **통과** | 검사를 실제 수행했고 관찰 결과가 사전에 정한 기대값·조건과 일치 | 입력/fixture, 명령 또는 수동 절차, 기대값과 실제값, 관련 AC |
| **실패** | 검사를 수행했으며 값·상태·제약이 기대와 불일치하거나 검증 과정에서 구현 결함이 확인됨 | 최소 재현 입력, 기대/실제 차이, 실패 위치·안전하게 정리한 오류 |
| **미실행** | 검사를 시작/완료할 수 없거나 결과를 판단할 근거가 부족함. 스크립트·도구·DB·권한 부재, 환경 장애, 미확정 계약 등이 해당 | 실행하지 못한 검사, 구체적 이유, 확인되지 않은 범위와 다음 조치 |

명령이 도구 부재나 환경 문제로 중단됐으면 해당 동작의 정확성은 미실행이다. 실제 assertion 불일치는 실패다. 관련 없는 검사는 선택하지 않고 ‘범위 밖’으로 적으며, 미실행 검사를 통과 수에 포함하지 않는다.

보고 형식:

```text
검증 범위: 변경 파일·데이터 경로·관련 AC
검사 | 상태(통과/실패/미실행) | 기대값 → 실제값 또는 미실행 이유 | 근거
남은 문제: 실패 수정 사항 또는 미실행 해소 조건
완료 판단: 선택한 필수 검사를 모두 통과했는지와 검증의 한계
```

- 일반 모드의 검증 계획과 실제 Plan Mode 결과를 구분한다. 계획·코드 읽기만 수행한 내용을 실행 결과로 보고하지 않는다.
- 선택한 필수 검사가 모두 통과하면 검증을 종료한다. 관련 없는 전체 검사 반복으로 범위를 늘리지 않는다.
- 실패가 있으면 검증 완료·배포 가능으로 보고하지 않는다. 요청 범위의 결함은 수정 후 실패 검사와 영향을 받는 검사만 다시 실행한다. 재시도할 근거 없이 같은 명령을 반복하지 않는다.
- 필수 검사 미실행이 남으면 ‘검증 미완료’로 보고하고 필요한 환경·결정·권한을 명시한다. 가능한 독립 검사는 계속 수행한다.
- 비밀값 노출 위험, 운영 DB에 대한 의도하지 않은 쓰기, 데이터 손상 가능성이 확인되면 해당 실행을 중단한다. 비밀값을 재출력하지 말고 원인과 필요한 안전한 다음 조치만 보고한다.
- 이 Skill은 커밋·push·병합·배포나 운영 DB 마이그레이션을 자동 승인하지 않는다. 해당 작업은 사용자 요청 범위를 따른다.
